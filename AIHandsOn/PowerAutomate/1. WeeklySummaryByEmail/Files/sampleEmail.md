[AI Apps 프로젝트] 1주차 주간보고

안녕하세요.

이번 주는 AI Apps 개발 프로젝트의 첫 주로, 전체적인 방향성과 요구사항을 정리하고 핵심 구성 요소들을 정의하는 데 집중했습니다. 우선 고객사와 두 차례 요구사항 정의 워크숍을 진행하면서 최종적으로 구현해야 할 주요 사용 시나리오와 시스템 간 연동 범위를 확정할 수 있었고, 이를 기반으로 전체 AI Apps 아키텍처 초안을 마련했습니다. 특히 Azure AI Foundry를 중심으로 Azure AI Search, Azure OpenAI, 내부 API 게이트웨이 등을 어떻게 배치할지에 대한 기술적 구성도를 작성해 고객과 공유했고, 문서형 데이터 기반 RAG 기능을 실질적으로 검증하기 위해 1차 테스트 환경을 구성하여 문서 인덱싱까지 완료했습니다.
다만, 진행 과정에서 예상과 달리 고객사의 내부 보안 정책으로 인해 테스트용 문서 전달 일정이 다소 지연되었고, 이로 인해 RAG 성능 검증도 제한적인 범위에서만 수행할 수 있었습니다. 또한 API 연동 범위가 초기 단계에서 예상했던 것보다 복잡해 고객 측에서도 스코프를 재검토해야 한다는 의견을 주셔서 향후 일정 조정이 필요할 것으로 보입니다. 현재로서는 고객 시스템 접근 계정 발급이 지연되고 있어 실제 데이터 기반의 통합 테스트 착수까지 최소 3~5일 정도 더 소요될 것으로 예상됩니다.
다음 주에는 Azure AI Search 기반의 1차 RAG 데모를 제공하고, API 연동 상세 설계 문서를 확정하는 작업을 우선적으로 진행할 예정입니다. 계정 발급 상황에 따라 빠르게 시스템 연동 테스트까지 이어갈 계획이며, 사용자 인터랙션 품질에 큰 영향을 주는 프롬프트 엔지니어링 방향성도 고객과 협의하여 세부 가이드라인을 잡을 예정입니다.
감사합니다.

[AI Apps 프로젝트] 2주차 주간보고

안녕하세요.

이번 주에는 RAG 기반 검색 품질 개선과 프롬프트 엔지니어링 고도화가 주요한 작업이었습니다. 지난주에 구성한 환경을 기반으로 Azure AI Search의 1차 RAG 검증을 진행했으며, 초기 정확도는 약 62% 수준으로 측정되었습니다. 이를 개선하기 위해 문서 스키마와 chunking 전략을 재정비하여 기존의 단순 규칙 기반 chunking에서 Semantic chunking을 혼합 적용하는 방식으로 전환했고, 그 과정에서 API 연동과 사용자 흐름을 고려한 전체 구조 설계도 함께 정리해 고객사 검토까지 완료했습니다. 또한 다양한 사용자 시나리오에서 일관된 응답 품질을 확보하기 위해 프롬프트 버전 8개를 제작해 비교 검증을 진행했습니다.
한편, 일부 OCR 품질이 낮은 문서에서 문맥 파악에 어려움이 있어 임베딩 품질이 떨어지는 문제가 확인되었고, 특정 프롬프트 조합에서는 모델의 응답 편차가 과도하게 발생해 하나의 통합된 프롬프트 전략이 필요하다는 의견이 내부적으로 제기되었습니다. 또한 고객사 내부에서 데이터를 정제하는 일정이 확정되지 않아 고품질 RAG 성능 확보 시점을 예측하기 어렵고, Azure OpenAI 사용 승인도 내부 보안 검토 절차로 인해 아직 대기 상태여서 모델 변경이나 기능 확장이 즉시 이루어지지 못하고 있습니다.
다음 주에는 프롬프트 엔지니어링을 더욱 개선하여 안정적인 응답 품질을 확보하는 데 집중할 예정이며, Hybrid RAG(벡터 + 키워드)를 활용한 검색 실험을 추가로 수행할 계획입니다. 이와 함께 API Mock 서버를 구축해 실제 API 연동 전 기능 흐름을 검증하고, Azure AI Foundry 프로젝트의 버전 관리 체계를 정립해 개발 환경을 안정화할 계획입니다.

[AI Apps 프로젝트] 3주차 주간 보고

안녕하세요.

3주차에는 검색 품질 개선과 Multi-Agent 구조 확정, 그리고 API 흐름 검증에 주력했습니다. 지난주에 예고했던 Hybrid RAG 기법을 적용한 결과, 검색 정확도가 78%까지 개선되어 문서 기반 질의응답의 품질이 안정적인 수준에 근접했습니다. 이를 바탕으로 고객사의 서비스 흐름에 맞춘 Multi-Agent 구조 초안을 정리했으며, 각 에이전트 간 역할 분리 및 메시지 전달 방식도 설계해 개발에 활용할 수 있는 구조적 기반을 마련했습니다. API는 아직 실제 연동이 어려운 상황이라 Mock API로 전체 응답 흐름을 검증했고, 사용자 UX 프로토타입도 제작하여 질의 요청부터 정보 검색, 최종 응답까지의 인터랙션을 시각적으로 검토할 수 있도록 지원했습니다. 프롬프트 가이드라인도 1.0 버전으로 문서화하여 고객에게 공유했습니다.
다만, 장문 문서에서 최신 정보와 과거 정보가 섞여 있는 경우 모델이 혼동하여 hallucination이 다소 발생하는 문제가 확인되었습니다. 이를 개선하기 위해 문서 chunk 경계를 다시 조정하고 추가적인 메타데이터 태깅 작업이 필요해 보입니다. 또한 고객 측에서 이번 주 중 새롭게 3개의 사용자 시나리오를 추가로 요청해 우선순위를 재정립할 필요가 있으며, 내부 시스템 접근 권한이 여전히 발급 대기 중이라 실제 데이터 기반의 API 연동 검증은 다음 주 이후로 넘어갈 가능성이 큽니다.
다음 주에는 실제 API가 연결되는 즉시 응답 속도와 예외 처리 흐름을 검증할 계획이며, Multi-Agent 시나리오 중 우선순위가 높은 두 가지 기능에 대한 개발을 본격적으로 진행할 예정입니다. 또한 사용자 테스트(UT) 준비를 위해 인터랙션 시나리오를 정리하고 문서 chunk 구조를 한 번 더 손보는 작업을 추진할 예정입니다.

[AI Apps 프로젝트] 4주차 주간보고

안녕하세요.

4주차에는 실제 API 연동, Multi-Agent 프로토타입 개발, 사용자 테스트(UT) 실행 등 본격적인 기능 검증 단계에 들어갔습니다. 우선 고객사로부터 API 접근 권한이 제공되어 실제 API를 연동한 후 응답 흐름을 점검했고, 응답 지연 구간과 속도 변동 원인을 분석하여 개선이 필요한 항목들을 정리했습니다. 또한 지난주 설계한 구조를 기반으로 Document Agent, Search Agent, Planner Agent로 구성된 Multi-Agent 프로토타입을 구현해 주요 기능 흐름을 시연 가능한 수준으로 개발했습니다. 사용자 테스트 1차도 진행하여 실제 사용자의 피드백을 바탕으로 개선이 필요한 포인트 6건을 도출했고, 이후 문서 재구성과 chunking 전략 고도화를 통해 전체 검색 정확도를 84%까지 끌어올렸습니다. 응답의 일관성을 위해 지식 기반 응답 템플릿도 정비했습니다.
하지만 API 응답 시간이 여전히 일정하지 않아 특정 요청에서는 AI 응답 품질이 저하되는 문제가 발견되었고, 일부 사용자 요구사항이 초기 스코프를 초과하는 것으로 확인되어 고객과 추가 협의를 진행해야 합니다. 또한 Multi-Agent 간 메시지 전달 구조가 간헐적으로 불안정해 로깅 및 트레이싱 체계를 강화하지 않으면 장애 원인 분석이 어려울 것으로 보입니다. 고객사에서 테스트 문서를 추가 제공하지 않아 새로운 시나리오에 대한 성능 검증 범위에도 제약이 있습니다.
다음 주에는 Multi-Agent 기능의 안정화와 로깅 구조 확립을 최우선으로 진행할 예정이며, 중간 데모 시나리오를 확정해 1차 데모를 제공할 계획입니다. 또한 API 장애 가능성에 대비해 fallback 설계를 추가하고, 프로젝트 중간점검 보고서를 작성하여 고객에게 공유드릴 예정입니다.
